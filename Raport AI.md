# AI in Software Testing — ChatGPT vs Manual Unit Tests

## Overview

This project analyzes how AI tools, specifically [ChatGPT](https://chatgpt.com?utm_source=chatgpt.com) (GPT-4o), can assist in generating unit tests for Java applications and compares the generated tests with manually written test suites.

The report focuses on a Java project containing classes such as:

* `User`
* `Card`
* `AuthenticationService`

and evaluates the quality of AI-generated tests using common software testing techniques:

* Boundary Value Analysis (BVA)
* Equivalence Partitioning (EP)
* Branch Coverage Testing

---

## Objectives

* Evaluate the usefulness of AI-generated JUnit 5 tests
* Compare manual vs autogenerated test quality
* Analyze coverage, correctness, and maintainability
* Identify strengths and limitations of AI-assisted testing

## Prompt Used

```text
Sunt student la informatică și am un proiect Java cu o clasă `User` care are:
- Un constructor: User(int id, String firstName, String lastName, Date birthDate,
  String email, String password, boolean active, List<Card> cards)
- O metodă statică: static String Crypt(String input)
- O metodă de instanță: void UpdateCards(List<Card> cards)
- O metodă: boolean isNull()

Generează teste unitare JUnit 5 pentru această clasă folosind:
1. Boundary Value Analysis (BVA)
2. Equivalence Partitioning (EP)
3. Branch coverage pentru metoda isNull()

Folosește Mockito unde este necesar.
```

## Example of AI-Generated Tests

```java
@Test
public void testCrypt_EmptyString() throws Exception {
    String result = User.Crypt("");
    assertNotNull(result);
    assertEquals(32, result.length());
    assertEquals("d41d8cd98f00b204e9800998ecf8427e", result);
}

@Test
public void testIsNull_FirstNameNull() throws Exception {
    User user = new User(1, null, "Doe", new Date(),
            "j@d.com", "pass", true, new ArrayList<>());

    assertTrue(user.isNull());
}
```

## Comparison: Manual Tests vs AI Tests

| Criteria            | Manual Tests                | AI-Generated Tests    |
| ------------------- | --------------------------- | --------------------- |
| Testing methodology | Explicit BVA, EP, Coverage  | Generated from prompt |
| BVA coverage        | More complete               | Missing some cases    |
| Exception handling  | Matches real behavior       | Sometimes incorrect   |
| Mockito usage       | Advanced dependency mocking | Limited mocking       |
| Branch coverage     | Full coverage               | Partial coverage      |
| Static dependencies | Handled with reflection     | Often ignored         |
| Writing time        | ~4 hours                    | ~10 minutes           |
| Manual fixes needed | None                        | Several adjustments   |

## Key Findings

### Advantages of AI Testing

* Fast generation of boilerplate tests
* Covers common edge cases automatically
* Useful starting point for test suites
* Reduces repetitive work

### Limitations

* Can hallucinate exceptions or method behavior
* Does not understand hidden architecture details
* Incomplete branch coverage without guidance
* May generate uncompilable code

## Conclusions

This experiment shows that AI tools like ChatGPT can significantly speed up unit test creation, especially for:

* Boundary tests
* Basic equivalence classes
* Initial test scaffolding

However, manual review remains essential for:

* Correct exception validation
* Complex dependency injection
* Complete branch coverage
* Architecture-specific logic

The best workflow is a hybrid approach:

1. Generate initial tests with AI
2. Review and refine manually
3. Extend coverage for real application behavior
